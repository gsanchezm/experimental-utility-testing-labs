## Lifecycle

Authoritative definitions are in protocol/change-control-v1.md. Summary:

DRAFT -> FROZEN-PRE-DATA -> (SUPERSEDED | AMENDED)

- **DRAFT** — editable; not yet approved; no data may be collected under it.
- **FROZEN-PRE-DATA** — approved by explicit human decision before any data is collected under that version; content is immutable from this point.
- **AMENDED** — terminal state of a frozen version replaced by a successor created after data collection began; the file stays on disk unchanged apart from its header, and the change (rationale, affected campaigns) is recorded in the change log.
- **SUPERSEDED** — terminal state of a frozen version replaced by a successor before data collection began under it; retained for the record, no longer governs any campaign.

## Versioning rule

Two stateless, unversioned log files carry no protocol state: protocol/CHANGELOG.md (approved changes, protocol/change-control-v1.md section 5) and protocol/unresolved.md (the protocol escalation log: protocol-level escalations mirrored by the ORCHESTRATOR, protocol/agent-governance-v3.md section 6, unchanged in substance from protocol/agent-governance-v1.md section 6, under which the file was created). protocol/CHANGELOG.md was created by the protocol v1 pre-data freeze of 2026-09-16; it holds one row per approved change and a separate "Non-substantive corrections" table, each newest last, and its newest rows record the post-E01 presence transcription into manifests/sut-manifest.yaml (2026-10-02; a non-substantive manifest row; PROTO-U16), the CI correction of the E03 environment-verification workflow (2026-10-03), and the freeze of protocol/agent-governance-v3.md with the AMENDED state of v2 (2026-10-03; PROTO-U20). protocol/unresolved.md was created on first use (PROTO-U01, 2026-09-17). As of 2026-10-03 it carries 20 rows (PROTO-U01…PROTO-U20): one is OPEN — PROTO-U02 (OPEN — deferred) — and the other nineteen are RESOLVED, some with a qualification written in their status cell (PROTO-U13, PROTO-U16, PROTO-U17, PROTO-U18, PROTO-U19, PROTO-U20); PROTO-U16 was resolved on 2026-10-02 by the post-E01 presence transcription (manifests/sut-presence-transcription-v1.yaml); PROTO-U20 was resolved on 2026-10-03 by the freeze of protocol/agent-governance-v3.md (manifests/agent-governance-v3-amendment-v1.yaml). This escalation log is distinct from the Open-Issue Register of protocol/study-design-v1.md, section 13, whose live counts are in manifests/study-manifest.yaml (`open_issue_register`; see "Current status").

A frozen version is never overwritten. Any modification to a frozen document creates a new version file with the version suffix incremented (for example, protocol/capability-rubric-v1.md -> protocol/capability-rubric-v2.md). The earlier file remains unchanged and its state is updated to AMENDED or SUPERSEDED per protocol/change-control-v1.md. Each version file carries its own header block stating its version and state.
