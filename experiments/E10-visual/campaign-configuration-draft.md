## 3. One execution, and the measurement

- **One execution** is, for each view of the condition in order, three captures in the fixed order A, B, A2 (as the brief), each in a **fresh browser context** (no cache, storage or cookies carried over) of headless Chromium at one viewport of **1280 x 900** CSS pixels, device scale factor 1, locale en-US, time zone UTC, reduced motion, animations disabled at capture, the caret hidden. Nothing is restarted between executions; the instance is provisioned once per job. Blocks, in order: **starting-state check** (the surface answers; for SUT-01 the API health answers and both accounts log in with the behavior the condition declares; for SUT-02 and SUT-03 the login is part of each load), **method** (the captures), **classification**, **record** (run manifest last). An exception before the first measured navigation is attributed to TOOLING, after it to the SUT (rule D-16 of E05).
- **Capture** is a viewport screenshot of the page at scroll position 0 after the page's own ready signal and the settle check: `document.fonts.ready`; every `<img>` of the page inside the viewport `complete`, waited for at most 5000 ms (`capture.settle.image_timeout_ms`; an image still pending after the bound is recorded as pending, and the natural width of each is recorded, so a broken image is a recorded state, not a missing one); then the layout wait: the boxes of the expected elements unchanged over two consecutive animation frames, with its own budget of 20000 ms (a capture whose layout never stops moving is `INCONCLUSIVE_READY_SIGNAL_MISSING` with the reason `LAYOUT_NOT_STABLE`). The image wait is bounded because the SUT-01 page of State B requests its placeholder again without limit (DRY_RUN round 4, decision E10-HARNESS-FIX-2). A capture's size is always 1280 x 900, so two captures are always comparable; a capture whose dimensions differ is `INCONCLUSIVE_CAPTURE_DIMENSION_MISMATCH` (a harness defect, never a non-detection). Full-page and element-scoped captures are not used, because they change dimensions with the content (the brief's "element-scoped captures" are replaced by boxes read from the DOM, below).
- **Comparison** is Pixelmatch (E10-D-13) with its library defaults, not tuned: per-pixel colour threshold 0.1, anti-aliased pixels detected and ignored (`includeAA` false), `alpha` 0.1. Recorded unchanged per comparison: the differing-pixel count, the compared-pixel count, `R` = differing / compared, and the diff image.
- **Expected-element boxes.** The elements named in the expectation of a view are located by their selectors in A (the baseline of the view) and in B. The set of elements considered is the one found **wholly inside the viewport in A**; B must show the same elements (an element absent from B is a recorded finding, not a validity failure, because a perturbation may remove it). For each element `e` the **region** is the union of its box in A and its box in B, clipped to the capture (a box of zero area, such as `#shift-target` in A, contributes nothing). `r(e)` is the number of differing pixels inside the region divided by the region's pixels. The first screen only is captured, so "every item" means every item that lies wholly inside the viewport; the uniform mechanism of each perturbation is stated in the evidence records (E10-D-4).
- **Detection rule (E10-D-14).** A view is *detected* when `R >= T_R` and `r(e) >= T_e` for **every** expected element considered. An execution is `DETECTED` when every view of the condition is detected. `T_R` and `T_e` are per condition and are fixed before the START by the calibration rule below; no threshold is read from a perturbed capture. The rule is conjunctive on purpose: a whole-frame ratio alone is dominated by differences the expectation does not name (the random prices, the first image and the aligned items of SUT-02, the signed-in user name of SUT-03), and a box alone would not show the expected difference was found rather than noise.
- **Calibration rule (written before any DRY_RUN; E10-D-14).** From the baseline-against-baseline comparisons (A against A2) of all DRY_RUN rounds of the condition, never from A against B: `T_R = max(F_R, 2 x max R_AA2)` and `T_e = max(F_e, 2 x max r(e)_AA2 over the expected elements)`, where `F_R = 0.0005` (0.05 % of the compared pixels, 576 pixels of a 1280 x 900 capture) and `F_e = 0.01` (1 % of a region's pixels) are floors, so that a baseline in which every pair is identical (all ratios 0) cannot turn one noisy pixel into a detection. The floors are fixed here, before any capture, and are not derived from data. The values are recorded per condition in a calibration record (`manifests/e10-calibration-v1.yaml`, class `E10_CALIBRATION_RECORD`, status LOCKED, with the DRY_RUN run ids it was computed from) that becomes an input of the START lock: at the lock the pair of each condition is written in `conditions[].thresholds` of the conditions file, in the Campaign configuration section of the README and in the record, and the measured workflow requires the three to agree. A measured run with null thresholds is refused; a DRY_RUN with null thresholds uses the floors and labels every result provisional. Only the rounds that ran under the implementation hash that the START locks feed the calibration, with at least six baseline pairs per view (two rounds of three executions); a round is repeated for a defect of the harness (a red job, a changed implementation hash), never because a baseline pair was noisy: a noisy pair raises the thresholds by the formula. After the record is written and the thresholds are put in the conditions file, one confirming DRY_RUN round runs on the non-provisional path; it verifies the path and is not used to adjust a threshold. The rule is not adjusted to the perturbed ratios.
- **Baseline-against-baseline record (false positive; E10-D-15).** For each view, `R_AA2 >= T_R` is a false positive of that view; the execution record is true when any view's is. The rule's box clause is not applied to A against A2 (no expected difference exists to meet); the per-box ratios of A against A2 are recorded beside it. (E08 applied only the whole-comparison clause to its baseline pair for the same reason.)
- **A capture counts only if the page showed its own content** (`required_ready`: the product grid, the inventory list, the cart container, the shelf, the page heading); a login page or an error page is `INCONCLUSIVE_READY_SIGNAL_MISSING`, never a non-detection.
- **Categories.** `DETECTED` (SUCCESS; matches expected), `NOT_DETECTED` (FAILURE; a recorded non-detection, not an error), `INCONCLUSIVE_READY_SIGNAL_MISSING`, `INCONCLUSIVE_CAPTURE_DIMENSION_MISMATCH`, `INCONCLUSIVE_EXTERNAL_IMAGE_NOT_LOADED` (the SUT-01 condition only: an expected image of State A, in A or in A2, did not load; attribution EXTERNAL, never a non-detection, E10-D-12), `START_SURFACE_NOT_READY` and `START_ACTIVATION_NOT_CONFIRMED` (ABORTED), `INTERRUPTED_` (ERROR), `STUB_NO_BUNDLE` (ERROR). Two situations that have no category of their own are `INCONCLUSIVE_READY_SIGNAL_MISSING` with the reason recorded: an expected group with no element wholly inside the viewport in State A (a detection or a non-detection over zero elements would both be wrong), and a timed capture (SUT-03 shift) taken more than 1000 ms after its target time (`CAPTURE_TIME_MISSED`). There is no catch-all: an undeclared label is kept with a note so that the analysis fails closed on it.
- **Denominators (E10-D-18, as E08-D-18).** The detection proportion of a condition is `DETECTED` over the valid measurements (`DETECTED` or `NOT_DETECTED`); every `INCONCLUSIVE_*`, `START_*`, `INTERRUPTED_` and `STUB_NO_BUNDLE` execution is reported with its count and attribution and sits outside that denominator. The false-positive proportion is the number of executions whose baseline record is true over the executions that have one. All N = 50 executions appear in the table of counts. No minimum number of valid executions is invented.
- **Reporting** (the analysis, later): per condition the proportion of executions that detect the expected difference and the baseline-against-baseline false-positive proportion, each with a Wilson 95 % interval; the ratios descriptive; per ecosystem the H5 count; no ranking and no composite; a near-certain result stated as controllability evidence of the condition and of the measurement, never as discriminating power.

## 6. Raw-data volume (open before the START package)

The README requires baseline, perturbed and comparison images. At 1280 x 900 a PNG is of the order of a few hundred kilobytes; with five images per view (A, B, A2 and two diff images) and up to three views (SUT-02 alone yields 15 PNGs per execution: nine captures and six comparison images), the campaign could reach several hundred megabytes. The size is measured in DRY_RUN round 1 and a retention rule is then put to the human research lead (E10-D-20): every image of every execution kept (the default of the README), or every diff image and every capture digest kept for every execution with the three captures kept for a stated subset. Neither is chosen here, and no image is dropped before the decision.
