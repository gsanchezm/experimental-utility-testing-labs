# AGENT-INSTRUCTIONS.md — Project Instructions for All Agents

These instructions are binding for every automated agent (and human operator) working in this repository; they override default behavior.

Study: Experimental Utility of Software-Testing Laboratory Ecosystems (EUS-2026-001). Protocol version v1. A system under test (SUT) is one of the six evaluated ecosystems listed in README.md. Repository root: the working directory (README.md, section 10).

## Rules

1. **This repository is scientific experimental infrastructure.** Every file is protocol, provenance, evidence, or a reproducible transformation of evidence; edit it with the care of a lab notebook.
2. **Never change frozen protocol files silently.** A file in state FROZEN-PRE-DATA or later is never overwritten; a modification creates a new version file and a change-log entry per protocol/change-control-v1.md.
3. **Never modify a SUT to make it score better.** An ecosystem is evaluated as found at its recorded commit or release; forks, patches, or configuration changes that alter observed capability invalidate the comparison.
4. **Never infer that a vendor's commercial testing product gives its demo SUT the same capability.** Only the evaluated ecosystem counts as evidence; a vendor's cloud or product features are not evidence about the demo ecosystem (protocol/evidence-rules-v1.md).
5. **Never assign comparative conclusions without recorded evidence.** Every claim about an ecosystem traces to an evidence record, referenced by its evidence_id (never by CSV row or line number), carrying one of the evidence statuses DOCUMENTED, SOURCE_VERIFIED, EXECUTION_VERIFIED, INFERRED (protocol/evidence-rules-v1.md).
6. **Never delete raw data.** raw-data/ is append-only after campaign freeze (raw-data/README.md).
7. **Raw observations must be immutable once a campaign is frozen.** Corrections are recorded as correction records or new derived datasets, never as edits to raw files.
8. **Derived results must always be reproducible from raw data.** Every derived dataset names its raw inputs, transformation script, and script version (derived-data/README.md, analysis/README.md).
9. **Every experimental run must record provenance.** A run manifest conforming to schemas/run-manifest.schema.json accompanies every run and identifies, at minimum, the campaign, the SUT, the protocol version, the environment_type, the tool versions (null only with a justification in notes), and the prompt_version used (null only for a human-executed run, per prompts/README.md rule 5). In E01, only EXECUTION_VERIFIED evidence requires this, as an execution verification record (protocol/evidence-rules-v1.md).
10. **Every SUT must be evaluated using the same applicable rules.** The same rubric (protocol/capability-rubric-v1.md), evidence rules, and procedures apply to all six ecosystems; a modality that does not apply is recorded as such, never skipped silently.
11. **Specialist SUTs must not be penalized for intentionally narrow scope.** SUT-04, SUT-05, and SUT-06 are baselines in their specialty; the profile is per-dimension, and there is no composite score in which narrow breadth could be traded against depth. A structurally absent surface is Score 0 with a structural_scope_note, never N/A; Experimental Breadth and Modality Depth answer different questions (protocol/study-design-v1.md, section 11).
12. **OmniPizza receives no privileged interpretation.** SUT-01 is one evaluated SUT, not the framework, the reference, or an expected winner; identical rules and identical evidence thresholds apply to it.
13. **Any protocol change after data collection begins requires: new protocol version; rationale; affected campaigns; explicit record in change log.** Procedure: protocol/change-control-v1.md.
14. **Mobilewright is the candidate mobile runner. Appium 3 is the fallback. Do not introduce Appium 2.** Mobilewright must pass the qualification gate (MQ1, MQ2, MQ3) before experimental use (protocol/mobile-runner-policy-v3.md, FROZEN-PRE-DATA and in force since 2026-10-02; its predecessors are v2, AMENDED 2026-10-02, under which both compatibility smokes were executed, and v1, AMENDED 2026-09-26, under which the gate was executed).
